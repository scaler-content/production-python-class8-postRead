Rebuild it

  
From unmeasured to controlled, step by step

  
Each step depends on the one before it. Click the steps in the order you would do this work yourself, first to last.

  

    

    

    

    

  

  
Why this order?You cannot fix what you have not measured, and you cannot trust a profile taken on a different run than the one you report. Streaming comes before the gates, because a lighter pipeline makes the gates easy to test on their own. The cache key is fixed before the cap is added, so a cap is never hiding a correctness bug underneath it. The comparison comes last, because it needs every other piece already in place.

The rule that decides itIf the whole thing must exist at once in memory, it is a list (or a list comprehension). If one item at a time is enough, and nothing needs to look back or sort the whole thing, a generator (or generator expression) is usually lighter.

Measuring

  

  

    
QuestionToolNote

    
How long did it take?time.perf_counter(), or bench.py --measure timeNever read the seconds of a run measured with tracemalloc

    
How much memory, peak?tracemalloc, or bench.py --measure memorySlows the run; measure time and memory in separate runs

    
Where does the time go?cProfile, or bench.py --measure profiletottime: the function alone. cumtime: the function and everything it calls

    
Which line, inside one function?line_profilerInstructor demo only; not installed for students by default

The four gates, in order

  

  

    
#GateCost if it stops here

    
1Eligible? (skip_reason, plain Python)Nothing: no cache read, no call

    
2Cached? (cache_key, a hash of the whole prompt)A cache read only

    
3Budget left? (CallBudget.take())Nothing new spent; status UNAVAILABLE, reason CAP_REACHED

    
4Ask the modelThe only gate that costs money
